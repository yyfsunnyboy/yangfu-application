# Potential Weaknesses

1. **演算法與程式競賽（如 TOI、APCS 實作）成績相對有限**：
   - 目前 APCS 實作僅 2 級分，未具備資奧（TOI）選拔營或全國資訊學科能力競賽決賽經歷。
   - **應對策略**：坦然承認目前主要投入於「系統架構、軟體工程與應用研究」，APCS 觀念達 5 級分證明基礎概念清楚；並在自傳與計畫中明確表達進入資工系後渴望扎實補強演算法與資料結構。
2. **研究中包含三人團隊合作，需精確釐清個人貢獻**：
   - 審查委員極可能質疑團隊成果中陽甫個人的具體程式碼量與核心貢獻度。
   - **應對策略**：嚴格遵守 `PROJECT_RULES.md`，主動標明隊友負責 PPO 與 RAG，陽甫負責 AST Healer、資料主線、狀態管理與系統整合，並備妥架構圖與可演示代碼。
3. **旺宏科學獎決賽成績尚未公布**：
   - 決賽最終名次未出。
   - **應對策略**：如實標註「入圍全領域全國決賽 20 強」，絕不預寫獲獎。

# Questions Reviewers May Ask

1. **「你說你做 AST Healer，那它具體修復了什麼？修復不了什麼？它的時間複雜度是多少？」**
   - *回答重點*：它針對 LLM 產生的語法錯誤與介面契約進行確定性語法樹遍歷與修復；無法修復深層語意邏輯錯誤；強調棄權機制（Abstention Mechanism），避免引發二次回歸（Regression）。
2. **「你的自適應學習系統用了 PPO 和 RAG，這部分你的貢獻到底是什麼？」**
   - *回答重點*：誠實說明 PPO 多目標推薦由蔡同學負責，Hybrid RAG 由林同學負責；我負責整套系統的介面契約定義、資料主線串接、狀態管理機制以及 AST 程式修復模組。
3. **「你 APCS 實作只有 2 級分，你如何證明自己能應付資工系繁重的高階程式與演算法課程？」**
   - *回答重點*：APCS 觀念 5 級分展現對程式邏輯、指標與遞迴架構的清晰理解；過去一年主力在於系統工程與真實專題研發，實作競賽題型熟練度尚有進步空間，這正是我在學習計畫中列為大一首要補強的目標。
4. **「你為什麼不選電機系或不分系，而一定要來資工？」**
   - *回答重點*：我在實際專案中感受最深、最想探索的是軟體如何具備確定性與容錯性，這屬於計算理論、程式語言與系統架構範疇，唯有資工系的完整訓練能給予解答。

# What We Must Not Overclaim

1. **嚴禁將 PPO 或 RAG 演算法宣稱為個人成果**。
2. **嚴禁宣稱 AST Healer 能修復所有程式邏輯錯誤**。
3. **嚴禁宣稱 AI 系統已在花蓮高商完成大規模實證並顯著提升學生成績**。
4. **嚴禁預先宣稱旺宏科學獎獲得特定名次（如一等獎、銀牌等）**。
5. **嚴禁誇大 APCS 實作成績或迴避實作 2 級分的事實**。
