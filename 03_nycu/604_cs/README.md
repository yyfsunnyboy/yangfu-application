# 申請目標

國立陽明交通大學 資訊工程學系 特殊選才（115/116學年度）

---

# 核心定位

**「在獨立研發 AI 自適應學習系統之資料主線與 AST 程式確定性修復模組的實踐中，深刻體認到單純應用層 API 呼叫的脆弱性，進而直面編譯解析、程式可靠度（Reliable Software）、系統容錯與資料架構的本質瓶頸；渴望進入全臺頂尖之陽明交大資工系，扎實研習演算法、計算機系統與軟體工程核心理論。」**

---

# 審查者應該在 30 秒內理解的三件事

1. **具備端到端全端軟體架構與系統整合實力**：非停留在 prompt 概念，而是主導 AI 自適應學習系統之資料架構、狀態機、前後端介面契約與多模組串接，並具備花蓮高商現場課堂試用部署經驗。
2. **具備深層程式可靠度意識與科學反思**：針對 LLM 生成錯誤研發 AST 語法遍歷修復與棄權機制（Abstention），並從東區科展挫折中徹底檢討重構基準測試，入圍第 25 屆旺宏科學獎全國決賽 20 強。
3. **具備強大自律底盤與明確的理論補強動機**：多線並行下維持高中四學期班排前五，清晰知曉自身在演算法與底層系統理論的欠缺，帶著真實軟體工程問題意識進入交大資工。

# 與其他申請版本的差異

- **對比交大百川 (01_baichuan)**：
  - 百川版本著重於「跨領域、自我探索與長期教育科技專案」；交大資工版完全回歸**「資訊科學理論、編譯原理、分散式架構、演算法與軟體工程」**的正統 CS 學門語境。

# 文件結構

- `T00_profile/`：一頁式資工申請人總覽（技能樹、專案成果、學業數據）。
- `T01_autobiography/`：自傳（從動手寫程式到面對大型軟體系統的成長歷程）。
- `T02_why_cs/`：申請動機（為何選擇交大資工？現有專案經驗與 CS 核心問題之連結）。
- `T03_technical_core/`：技術核心（AST Healer、確定性語法修復、棄權機制、基準測試與對照實驗）。
- `T04_system_engineering/`：系統工程（AI 教學系統架構、資料流程、教師/學生端介面、課堂部署）。
- `T05_external_validation/`：外部驗證與競賽（育秀盃金獎、神通冠軍、旺宏決賽、科展反思）。
- `T06_study_plan/`：學習計畫（演算法與資料結構、計算機組織、作業系統、編譯器設計、軟體工程之修課規劃）。
- `T07_supporting_evidence/`：佐證資料彙編（成績單、APCS、英檢證書、足球出賽紀錄）。
- `final/`：最終送件版 PDF 與輸出文件。
